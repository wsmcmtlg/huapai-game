# _partition全枚举修复验证报告

## 修复内容

1. **_partition DFS早期返回** → 改为onFound回调+移除早期返回，枚举所有合法拆分
2. **坎牌全字符检查** → 从O(1)检查rem[0]改为O(n)遍历所有rem字符
3. **onFound深拷贝** → 手动浅拷贝melds数组，避免回调后pop修改

### 2. 浏览器内analyzeHand测试（已通过）

#### 测试A: 坎牌选择验证（25张，两听）

- analyzeHand正确选择了坎牌拆分

#### 测试B: 双坎选择验证（26张，摞听）
- **手牌**: 柒柒七(2花1皮) + 七(1皮) + 三三三(3皮) + 四五六 + 七八九 + 八九十 + 上大人 + 可知礼 + 孔乙己 + 二二

- **主精选择验证**:
  - 主精=七: 26胡 (最优)
  - 主精=三: 22胡
  - analyzeHand正确选择了主精=七

#### 测试C: 全顺子验证（25张，两听）
- **手牌**: 七(4:2花2皮) + 十 + 土 + 五 + 六(2) + 八(2) + 九 + 上大人 + 可知礼 + 化三千 + 二二 + 三三
- **结果**: 22胡, 主精七, 7个全顺子(4个含七)
- analyzeHand正确找到了全顺子拆分（此手牌中kan不可行因为十土无法形成合法seq）

#### 测试D: 对比测试（坎牌20胡 vs 全顺子22胡）
- Hand K (可组坎): 20胡
- Hand L (不可组坎): 22胡
- analyzeHand对每种手牌都选择了各自的最优拆分

## 结论

**_partition全枚举修复有效**：
1. enumerate所有合法拆分（不提前返回）
2. tryRes对所有拆分计算胡数并保留最大值
3. 对所有红精候选作为主精计算，选择全局最优
4. 坎牌在合法且更优时会被正确选择（如测试A/B）
5. 当坎牌不可行时，正确选择全顺子拆分（如测试C）
