湖北公安花牌游戏 - 代码详细说明

本文档详细说明湖北公安花牌游戏（单文件 HTML 实现）的完整代码架构、数据模型、游戏规则、AI 系统及关键技术细节。代码文件：step5-hu.html，约 8159 行，1.08 MB，单文件自包含 Web 应用。

1. 游戏概述

湖北公安花牌是一种地方性字牌游戏，使用 22 种字牌（上、大、人、可、知、礼、三、五、七、化、千、孔、己、二、四、六、八、十、子、土、乙、九），每种字牌 5 张（精牌 3 皮 + 2 花，非精牌 5 皮），共 110 张。另有 2 张"赖子"（万能牌），总牌数 112 张。

本实现为单文件 HTML 应用，包含完整的游戏逻辑、AI 对战、音效系统和可视化界面。支持 3 人游戏（庄家 + 2 旁家），玩家与 2 个 AI 对战。

4. 游戏流程（生命周期）

4.1 整体流程

initGame()
  ├─ generateDeck()        → 生成112张牌并洗牌
  ├─ 发牌：庄家26张，旁家各25张
  ├─ 庄家摸1张 → 手中26张
  ├─ checkDealerZhaAndHu() → 检测扎牌/胡牌选项
  └─ 等待玩家操作

[玩家操作循环]
  ├─ 出牌: playCard() → checkOpponentResponse()
  ├─ 旁家响应: 碰/招/扎/吃/过
  ├─ passToNext() → 流转到下一家
  ├─ opponentAutoPlay() → AI自动出牌
  └─ 回到庄家 → animateDealerDraw() → checkDealerZhaAndHu()

[游戏结束]
  ├─ endGame() → 余牌为0流局
  ├─ dealerHu() → 庄家自摸胡
  ├─ checkOpponentHu() → 旁家胡牌
  └─ showSettlePanel() → 显示结算面板

4.2 发牌流程（initGame）

generateDeck() 生成 112 张牌：22 种字牌各 5 张（精牌 3 皮 + 2 花，非精牌 5 皮）+ 2 张赖子。使用 Fisher-Yates 洗牌算法。发牌顺序：庄家 26 张 → 下家 25 张 → 上家 25 张。庄家再摸 1 张，手中共 26 张。

4.3 出牌流程（playCard）

庄家双击手牌触发 onDblClick → playCard(el)：

  1. 验证：检查 G.locked、G.gameOver、phase 等
  2. 从 handCards 中移除该牌
  3. 从 cardEls 中移除对应 DOM 元素
  4. 调用 addDiscardCard() 添加到弃牌池
  5. 调用 trackCardUsed(ch, 'discard') 记录出牌
  6. 设置 G.lastPlayedChar = ch
  7. 调用 checkOpponentResponse() 检查旁家响应

4.4 旁家响应流程（checkOpponentResponse）

按顺序检查每个旁家：

  1. 胡牌检测：checkOpponentHu() — 检查旁家是否能胡（自摸或捉统）
  2. 招牌检测：手牌中是否有 3 张同字（含赖子）
  3. 碰牌检测：手牌中是否有 2 张同字
  4. 吃牌检测：听牌状态下是否能形成顺子或对子
  5. 过：无响应时 passToNext()

4.5 庄家摸牌后检测（checkDealerZhaAndHu）

庄家每次摸牌后调用，按优先级检测：

  1. 胡牌检测：checkDealerSelfHu() — 是否能自摸胡牌
  2. 穿牌检测：已有扎牌且摸到同字（含赖子通配）
  3. 泛牌检测：已有招牌/扎牌 + 手牌中有同字
  4. 扎牌检测：手牌中是否有 4 张同字（含赖子）
  5. 招牌检测：手牌中是否有 3 张同字
  6. 碰牌检测：手牌中是否有 2 张同字

数字顺子（8 种）：乙二三、二三四、三四五、四五六、五六七、六七八、七八九、八九十

5.4 听牌规则

  • 两听：7 组型牌（基础/扩展牌型）+ 2 眼（对子或半顺子）
  • 摞听：8 组型牌（基础/扩展牌型）+ 2 眼（对子或半顺子）
  • 吃牌：旁家只有在听牌状态才能吃他人打出的牌

5.5 胡牌规则

  • 最低胡数：17 胡（MIN_HU = 17）
  • 记分规则：17-21 胡得 3 分，每多 5 胡加 1 分
  • 主精：玩家根据手中牌型确定（最大胡数原则）
  • 限两对：胡牌前最多两次碰牌机会
  • 胡牌不变量：7 个基础/扩展牌型 + 2 眼（两听），或 8 个基础/扩展牌型 + 2 眼（摞听）

6. 胡牌算法（analyzeHand）

6.1 算法架构

胡牌检测是整个游戏最复杂的部分，采用递归回溯 + 剪枝策略：

analyzeHand(cards, preMelds)
  └─ _analyzeHandInner(cards, preMelds, allowChuanWildSwap)
       └─ _analyzeHandCore(cards, preMelds)
            ├─ tryRes(melds)        → 尝试将结果转为标准格式
            ├─ enumEyeCandidates()  → 枚举所有可能的眼（对子）
            ├─ trySingleEye(eye)    → 尝试单眼方案
            └─ tryTwoEyes(eye1,eye2)→ 尝试两眼方案（两听/摞听）

6.2 核心拆分器（_partition）

_partition(counts, wildList, wildUsed, handCards, melds, depth) 是递归拆分引擎：

  1. 将手牌按字符统计数量（counts 字典）
  2. 找到第一个 count > 0 的字符
  3. 尝试将其匹配为：顺子、坎牌、对子、碰牌
  4. 赖子通配：用赖子补齐不足的牌数
  5. 递归处理剩余牌，直到所有牌分配完毕
  6. 剪枝：余牌数 % 3 快速失败

6.3 胡数计算（_calcTotalHu）

10. 关键技术细节

10.1 显示系统（displayChar）

displayChar(cardData) 根据 cardData.v 决定显示花精还是皮精：

  • v="flower"：三→叁、五→伍、七→柒、乙→壹、九→玖
  • v="skin" 或 undefined：显示原始字符
  • 赖子始终显示"赖"

10.2 扎牌锁区（renderLockArea）

扎牌（暗杠）在锁牌区渲染，使用 displayChar(card) 显示每张牌。穿牌/泛牌后升级为明牌区显示。

10.3 赖子通配规则

  • 赖子只能通配三、五、七（WILD_USABLE = new Set('三五七')）
  • 赖子不能当乙、九用
  • 赖子不能当赖子用
  • 赖子可参与扎牌→穿牌升级
  • 赖子计胡：最少当花精 +2，若本场主精 +4；主精赖子对子计 8 胡

10.4 碰牌进阶

碰牌可升级为扎牌→泛牌，或招牌→泛牌。碰牌除计胡计句外已完全丧失自由度，不参与任何后续操作。

10.5 换扎系统

当扎牌后摸到同字时触发换扎对话框（huanzha-pick-overlay），玩家可选择：

  • 换扎：用新牌替换扎牌中的皮精/赖子
  • 穿牌：升级扎牌为穿牌
  • 仅解锁：释放扎牌

13. 游戏状态机

[INIT] → 发牌 → [DEALER_DRAW] 庄家摸牌
  → [CHECK] checkDealerZhaAndHu
    ├─ 可胡 → [HU_BUTTON] 显示胡牌按钮
    ├─ 可穿 → [CHUAN_BUTTON] 显示穿牌按钮
    ├─ 可泛 → [FAN_BUTTON] 显示泛牌按钮
    ├─ 可扎 → [ZHA_PICK] 扎牌选择弹窗
    ├─ 可招 → [ZHAO_BUTTON] 显示招牌按钮
    ├─ 可碰 → [PEN_BUTTON] 显示碰牌按钮
    └─ 无操作 → [DEALER_PLAY] 庄家出牌阶段
  → [DEALER_PLAY] 庄家双击出牌
  → [WAITING] checkOpponentResponse
    ├─ 旁家胡 → [OPPONENT_HU]
    ├─ 旁家招 → [OPPONENT_ZHAO]
    ├─ 旁家碰 → [OPPONENT_PEN]
    ├─ 旁家吃 → [OPPONENT_CHI]
    └─ 旁家过 → [NEXT_PLAYER]
  → [OPPONENT_PLAY] AI自动出牌
  → [NEXT_PLAYER] passToNext
  → [DRAW] 摸牌
  → [CHECK] ...循环

[GAME_OVER] 条件：
  ├─ 余牌为0 → 流局
  ├─ 庄家自摸胡
  ├─ 旁家胡牌
  └─ 旁家捉统胡
