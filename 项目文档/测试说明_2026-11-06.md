# 测试说明（LHP 交付包内）

> 这份测试套件与 Git 仓库 `wsmcmtlg/huapai-game` 的 `main` **保持同步维护**：
> 仓库每次改动都会跑全套，本目录是同步留档的副本，改了规则/计胡/AI 后可直接在此复跑验证。

## 一、怎么跑

**方式 A：一键跑全套 Windows**

双击 `hu_tests\run_all.bat`

**方式 B：命令行逐项跑**

```bat
cd C:\Users\Administrator\Desktop\LHP

:: 必须先提取核心代码（测试依赖 hu_tests\hu_core_current.js）
node hu_tests\extract_core.js step5-hu.html hu_tests\hu_core_current.js step5-hu_backup_before_flowskin_swap.html hu_tests\hu_core_before.js

:: 然后逐项执行（也可只跑关心的那几项）
node test_hu_tables_complete.js
node test_result_shape.js
...
```

**方式 C：Linux / Git Bash**

```bash
bash hu_tests/run_all.sh
```

## 二、环境要求

- **Node.js**（本机 v24 已验证）
- **不需要 Python**（`extract_core` 已提供 Node 版；`hu_tests/run_all.bat` 会在无 Python 时自动回退）
- 依赖文件：`measure_winrate.js`（测量器，多数测试会 require 它）、`step5-hu.html`（被测游戏本体）

## 三、21 个测试脚本一览

| 脚本 | 作用 | 断言要点 |
|---|---|---|
| `test_hu_tables_complete.js` | 精牌查表全量 | 红精+黑精 × 对/坎/扎/招/穿/泛 共 39 项组合 |
| `test_hu_regression.js` | 计胡回归 | 穿牌花皮重分配 70→84、无交换空间不误改 |
| `test_hu_flowskin_swap.js` | 穿牌重分配专项 | 70→84 |
| `test_hu_chuan_032.js` | 穿牌 3皮2赖 | 41→67 |
| `test_chuan_table.js` | 红精穿牌查表 | 6 条表驱动 |
| `test_hu_perf.js` | 性能 | 判胡耗时在 120ms AI 预算内 |
| **`test_hu_structure.js`** | 胡牌结构铁律 | **必须 8 圆句 + 1 眼；7+2 不算胡；赖只通配三五七** |
| **`test_result_shape.js`** | 结果对象形状 | 判胡/听口/结算字段齐全，渲染不出现 `undefined` |
| **`test_hu_total.js`** | 胡数兜底 | `totalHu` 必须是数值 |
| **`test_opp_hu_settle.js`** | 旁家胡牌结算 | `opponentHu` 必须存在、会调用结算面板 |
| **`test_opp_meld_cards.js`** | 旁家明牌兼容 | 明牌组是"字字符串"时判胡不抛错 |
| **`test_peng_chi_rules.js`** | 碰/吃规则 | 碰限两次、第三次须捉铳、吃只能吃即胡 |
| **`test_tong_win_shapes.js`** | 牌型级（吃统） | 两听口凑顺/凑碰；摞听赖 14 字能胡 / 8 字不能 |
| **`test_fan_choice.js`** | 泛牌多候选 | 多候选必须弹选择框，不得静默取第一个 |
| **`test_wild_discard.js`** | 赖子保护 | 四级 AI × 300 次出牌，从不主动打赖 |
| **`test_prototype_flex.js`** | 原型验收 | 用户 28 张原型：22 字全胡、108/64 胡数 |
| `test_eps.js` | AI 人味扰动 | L0~L3 的 ε 触发与落点 |
| `test_ai_concede.js` | 止损模式 | 弱牌+威胁+晚局才止损 |
| `test_ai_feed.js` | 喂牌 | 便宜家识别、feedScore、过牌降权 |
| `test_ai_risk.js` | 放铳风险 | 明牌胡数加权、riskCost、estPoints 阶梯 |
| `test_profile.js` | 跨局建档 | 只记人类位0、损坏档案不炸 |

## 四、测量工具（与本目录同级）

| 文件 | 用途 |
|---|---|
| `measure_winrate.js` | 胜率/荒庄测量（`--level 0~3 --games N --seed 20261027 --chuan hu-only`） |
| `analyze_draw_cause.js` | 荒庄成因拆解（听不了 / 听得晚 / 摸不到） |

常用命令：

```bat
node measure_winrate.js --level 3 --games 150 --seed 20261027 --chuan hu-only
node analyze_draw_cause.js --level 3 --games 120 --seed 20261027
```

## 五、维护约定

1. **改规则/计胡/AI 后必须先跑 `run_all.bat`**，全绿再提交
2. 修 bug 时**顺手补一条断言**（本轮 6 个新测试都是这么来的：结构铁律、形状、赖保护、泛牌可选、旁家结算、明牌兼容）
3. 新增测试要同时加进 `hu_tests/run_all.bat` 与 `run_all.sh`
4. 命名统一 `test_*.js`，直接 `node test_xxx.js` 可跑，失败时进程退出码非 0
