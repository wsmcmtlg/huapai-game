# 诊断报告：桌面 LHP 花牌游戏启动失败

日期：2026-11-26
对象：`C:\Users\Administrator\Desktop\LHP`
结论：**启动器依赖外部 Python，而该依赖在 PATH 中缺失 / 路径脆弱，导致双击后游戏无法启动。已改用 Windows 自带 PowerShell 静态服务器，彻底摆脱 Python/Node 依赖。**

---

## 一、症状

双击启动脚本后游戏页面打不开（或报「python 不是内部或外部命令」）。

## 二、排查过程与证据

| 检查项 | 结果 |
|---|---|
| `python` 是否在 PATH | ❌ 未找到 |
| `py` 是否在 PATH | ❌ 未找到 |
| `node` 是否在 PATH | ❌ 未找到 |
| `启动游戏.bat` 硬编码路径 `…\WPS 灵犀\python-env\python.exe` | ✅ 存在，实测 **Python 3.12.13** 可运行、`http.server` 模块正常、可监听 8765 |
| `启动游戏_PWA.bat` 使用裸 `python` 命令 | ❌ 依赖 PATH，而 PATH 里没有 python → 必失败 |

## 三、根因

LHP 里有两个启动脚本，依赖方式不同：

1. `启动游戏.bat`：用硬编码完整路径调用 WPS 灵犀自带的 Python。此路径**当前有效**，但极其脆弱——WPS 灵犀一旦升级/移动/卸载，该路径即失效，游戏再次打不开。
2. `启动游戏_PWA.bat`：用裸 `python -m http.server`，**完全依赖 PATH**。本机 PATH 中无 python，双击必然失败。

用户最可能点击了 `_PWA` 脚本，或 WPS 灵犀更新导致 Python 环境一度失效。

**本质：启动器把游戏可用性绑定在"外部 Python 环境"这个易变因素上。** 而游戏本身是纯静态文件（HTML + 图片 + 音频），只需要一个静态文件服务器，完全不需要 Python。

## 四、修复方案（已实施）

新增 `serve.ps1`——一个用 **Windows 自带 PowerShell（System.Net.HttpListener）** 实现的零依赖静态服务器：

- 不依赖 Python / Node / 任何第三方运行时
- 端口 8765 被占用时自动 +1 重试（最多 30 个）
- 先起服务、就绪后再打开浏览器（消除"连接被拒绝"竞态）
- 带 MIME 映射、目录穿越防护、404/500 处理
- 支持中文文件名与子目录（cards/、sounds/、icons/）

两个启动脚本改为统一调用它：

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0serve.ps1" -Port 8765 -Bind 127.0.0.1 -OpenUrl "step5-hu.html"
```

## 六、遗留与建议

1. **建议以后只用 `启动游戏.bat`**（本地游玩即可，无需 PWA 脚本）。
2. 若需要手机/局域网访问（0.0.0.0 绑定），需额外用管理员添加 URL ACL，见《手动修复手册》附录。
3. `serve.ps1` 已同步回 Git 仓库 `huapai-game` 根目录，后续维护以仓库为准。
