## 1. 总览：L3 在四级 AI 里的定位

### 1.1 四级难度

难度由 `G.aiLevel` 管理（默认值在 `G` 定义里，`step5-hu.html:2434`）：

| 级别 | 名称 | 出牌策略 | 一句话定位 |
|---|---|---|---|
| 0 | 菜鸟 | 纯随机（30% 概率直接随机，否则基础启发式） | 陪练沙包 |
| 1 | 高手 | 基础启发式 + 听牌感知（`_aiSmartDiscard`） | 会听牌 |
| 2 | 大师 | 听牌感知；`G._lv2Deep=true` 时升级为老千深度出牌 | 会记牌+听牌 |
| 3 | **老千** | **完整记牌 + 深度听牌 + 攻防一体（`_aiL3Cheat`）** | 本任务主角 |

级别常量：`AI_LEVELS`（`step5-hu.html:2231`），`G.aiLevel` 初始值 `3`（`step5-hu.html:2434`）。

> 注意：在正常对局里，位 0 是**人类庄家**，位 1/位 2 才是 AI 旁家；L3 策略跑在旁家（`aiPickDiscard` 的 `playerIdx ∈ {1,2}`）上。测量（measure）模式下才把 L3 挂到位 0。

### 1.2 设计目标

`_aiL3Cheat` 注释自述（`step5-hu.html:9535`）：**"完整记牌 + 深度听牌 + 攻防一体"**。其核心思路在代码注释 `step5-hu.html:9536-9540` 写得很直白：

> 花牌胡牌门槛 17 胡，而顺子成副几乎不计胡（红固定顺 1 胡、数字顺 0 胡）——胡数必须靠精牌坎/扎/招/穿/泛（查表 5~48 胡）。本引擎评估一手牌的"可达胡数潜力"，指导 AI 主动构造精牌牌型（双精朝坎走、有坎朝扎走、扎了朝穿走）。

也就是说，L3 与 L1/L2 的本质区别不是"会不会听牌"，而是**多了一个"朝精牌牌型走"的胡数方向感**，外加**记牌 + 危险规避 + 对手建模 + 止损/喂牌**的完整攻防层。


## 2. 出牌决策

### 2.1 入口与赖子保护（`aiPickDiscard`，8203）

- 先跑 `_aiPickDiscardCore` 拿到一个下标。
- **赖子保护**（8205-8216）：若选中的是赖子（`WILD_CHAR === '赖'`，2366），则把赖子从手牌中剔除，在"非赖子"子手上重跑一次核心策略，再把结果下标映射回原手牌下标。只有"整手全是赖子"这种极端情况才会真的打出赖子。
- 这段是 try/catch 包裹的包装层，异常时退回第一次的选择。

### 2.2 分流与 ε（`_aiPickDiscardCore`，8220）

- 空手返回 `-1`，单手返回 `0`（8221-8222）。
- **ε 随机扰动**（8225-8232）：默认表 `{ 0:0.10, 1:0.15, 2:0.075, 3:0.015 }`，可用 `G._eps[level]` 覆盖。**L3 的 ε = 0.015（1.5%）**。
  - 连败粘性：`playerIdx !== 0` 且 `_stickyEase()`>0 时，`ε += ease × 0.05`（最多 +0.15）。
  - 若 `Math.random() < ε`，直接随机出一张（含人味，见第 9 节）。
- **L3 分流**（8261-8267）：`hand.length >= 5` → `_aiL3Cheat`；否则回退 `_aiSmartDiscard`。异常时 `console.warn` 并继续（不崩）。

### 2.3 `_aiL3Cheat` 三段式（9584）

#### 第一层：候选预筛选 + 逐张听牌

- `_aiPerfStart(120)` 起 120ms 预算，`_aiClearTingCache()` 清缓存（9602-9604）。
- 候选 = `_aiPreFilterCandidates(hand, playerIdx)`（见 2.4）的 **top-8**，再**并上全部 uniqueChars**（9613-9617）——保证不漏掉任何高价值候选（预筛选只是排序优先级，不是硬裁剪）。
- 对每个候选，模拟打出该字 → `_aiCalcTingInfoCached(simHand, preMelds)`，得到 `{canTing, maxHu, tingCount, tingChars, canTingStruct, maxHuStruct}`，存入 `tingMap[ch]`（9629-9641）。每次迭代前 `_aiPerfCheck()`，超时即断。

#### 第二层：外部可见度（`exposureScore`，9643-9671）

- 扫弃牌池 DOM：每个同字 `.card-char` 计 `+0.5`；带花牌反向映射（柒→七、叁→三、伍→五、壹→乙、玖→九）。
- 扫旁家明牌区（`analyzeOpponentMelds` 汇总 pen/zhao/chuan/fan/zha 字面）：每个同字计 `+1`。
- `exposure` 越大 = 该字在外面露脸越多。

#### 第三层：综合评分（9673-9959）

先取上下文变量（9675-9709）：`phaseFactor`（阶段系数）、`defenseFactor`（攻防系数）、`gamePhase`、`strategyMode`、`concedeMode`（止损）、`feedTarget`（喂牌目标）、`behaviorGuesses`（旁家行为听牌猜测）、`_curPot = _aiHuPotential(hand, preMelds)`（当前胡数潜力）、以及 Phase 9 四规则与 Phase 10 档案。

然后对每个候选算 `discardPriority`（越高越该出），分两条分支：

**A. 能听牌分支**（9777-9792，精确规则 + 阶段系数）：

```
tingBase   = 止损? 1000 : 10000
tingMult2  = 止损? 10   : phaseTingMult（阶段听牌权重）
discardPriority = tingBase
                + ting.maxHu     * 100 * tingMult2
                + ting.tingCount * 50  * tingMult2
                + tingEffectiveness * 30
```

`tingEffectiveness`（9783-9788）= 对 `ALL_22_CHARS` 中 `getRemainingCount>0` 的字，求平均外部剩余张数，用来近似"听的口还剩多少张在外面"。

**B. 非听牌分支**（9794-9818，启发式综合分）：

```
discardPriority = -retainValue
                + trackSafety
                - dangerPenalty × defenseFactor.dangerMultiplier
                + visibilityBonus
// 胡数潜力损失：打出后潜力跌多少就罚多少 ×8
if (potDelta > 0) discardPriority -= potDelta * 8
// 结构听牌感知：打出后是否仍"结构听"
if (!ting.canTingStruct) discardPriority -= 500   // 打出后全拆散 → 保留
else                     discardPriority += 100   // 打出后仍结构听 → 鼓励换牌向胡数发展
// 规则1 大胡方向：精牌潜力损失额外罚（做大不做小）
if (bigHuDirB && potDelta>0 && !G._noBigBias) discardPriority -= potDelta * 6
// 规则3 撒灰：轻量喂胡另一旁家
if (feedOtherB && !concede) discardPriority += _aiFeedScore(ch, feedOtherB) * 12
// 双向牌流：卡下家（下家疑似需要 → -8）
//           喂上家（上家无扎且不危险且自己不守 → +10）
// 规则4 窄听口早期换向：结构听但胡数<20且盘中早期 → +25
// 攻防：安全牌奖励 / 冒险奖励
// 止损喂牌：feedTarget 存在时 + feedScore × 30
```

最后非听牌（或止损下的听牌）分支整体乘 `phaseFactor.aggression`（9820-9823）。

### 2.4 候选预筛选（`_aiPreFilterCandidates`，9079）

这是一个**不调用 `analyzeHand` 的廉价启发式预排序**，把 ~20 个字面压到 top-8，给 `_aiSmartDiscard`/`_aiL3Cheat` 省性能。

对每个唯一字面（`cnt > 3` 的四张直接跳过）算 `priority`（越低越应出，但这里只用于排序取 top8）：

```
retainScore = cnt==1 ? 1 : cnt==2 ? 3 : cnt==3 ? 7 : 0
           + (赖 ? 50 : 0)
           + (JING_CHARS ? 4 : 0)
           + 每个"该字参与的、且对子字在手的口" +2
trackSafety = remain<=0 ? 12 : remain<=1 ? 8 : remain<=2 ? 4 : 0
priority    = -retainScore + trackSafety
            - (danger + riskCost×0.5) × defenseFactor.dangerMultiplier × 15
priority    ×= phaseFactor.aggression
```

排序后 `slice(0, 8)`（9134-9138）。

### 2.5 选最优

- `scored` 按 `discardPriority` 降序排序（9828-9829）。
- 若最高分是听牌且非止损（9832-9904）：**听牌质量二次评估**——
  - 听牌张数 `actualTingCount` = Σ 各听牌字的 `getRemainingCount`（9856-9859）；
  - 听牌安全度 `avgTingDanger`/`avgTingRisk`（9863-9870）；
  - 综合分 = `actualTingCount×30 + maxHu×15 − avgTingDanger×30 − avgTingRisk×25`（9872-9873）；
  - **听死牌**（所有听牌字外部剩余 0）→ `−500`（9875-9879）；
  - **防守听牌**：最优听牌的出牌字 `getDangerScore > 0.9` 且存在危险度 `<0.6` 的其他听牌方案 → 换用安全方案（9887-9899）。
- 否则（非听牌）：危险阈值 `dangerThreshold = 止损?0.25 : 防守?0.4 : 0.7`（9917），逐候选检查 `effectiveRisk = max(danger, behaviorDanger) + riskCost×riskFactor`（`riskFactor = 防守?1.0:0.6`，9928-9929），`effectiveRisk − feedAllow < threshold` 且 `priority > -100` 则选中（9918-9935）。
- **兜底**（9937-9959）：选 `danger + riskCost×riskW` 最低者（`riskW = 止损?1.0:0.6`），止损且存在喂牌目标时优先 `feedScore` 高者、同分取风险低者。即"两害相权取其轻"。

## 3. 听牌感知

### 3.1 核心：枚举 22 字面模拟摸牌（`_aiCalcTingInfo`，8428）

- 输入 `simHand`（打出某张后的手牌）+ `preMelds`（已成型副）。
- 对 `ALL_22_CHARS`（22 个字面，7894-7895）逐一：
  - `simCards + 摸到 tch` → `analyzeHandLoose(testCards, preMelds)`（6226，loose 版同时给结构信息）；
  - `result.isWin` → `canTing=true, tingCount++, tingChars.push(tch), maxHu = max(maxHu, totalHu)`；
  - `result.melds.length > 0` → `structCount++`（结构听牌，胡数可能未达 17）。
- 返回 `{canTing, maxHu, tingCount, tingChars, canTingStruct, maxHuStruct}`。

这就是"打出某张后是否听、听几口、最高几胡"的全部来源，是**精确规则**（依赖 `analyzeHandLoose`/`analyzeHand` 的真实胡牌判定器），不是启发式。

### 3.2 缓存版（`_aiCalcTingInfoCached`，9051）

- key = 手牌排序串 + preMelds 指纹（`_aiMakeCacheKey`，9039）。
- 命中直接返回；最多缓存 100 条，超出删最早一条（9061-9067）。
- 每次决策前 `_aiClearTingCache()`（9072）同时清掉听牌缓存和对手胡数缓存 `_aiHuEstCache`。

## 4. 胡数潜力引擎（`_aiHuPotential`，9542）

**用途**：给一手牌估"可达胡数潜力"，指导"朝精牌牌型走"。输入是字符串数组（无花/皮信息），所以**精牌查表期望全部用常数近似**（注释 9540 明说"校准阶段精化"）——**这是一组启发式常数，不是精确胡数**。

### 4.1 常数表（9549-9581）

**红精（三/五/七）潜力**（9552-9560）：

| 张数 n | 无赖时 | 有赖（≥1）时 | 含义 |
|---|---|---|---|
| 1 | +4 | +4 | 单精：进顺/坎的期望 |
| 2 | +8 | +14 | 双精：+赖=扎料（扎 14~18） |
| 3 | +15 | +24 | 坎：可扎（12~24）可穿（28+） |
| ≥4 | +30 | +30 | 4 张：扎成，穿潜力大 |

**黑精（乙/九）潜力**（9562-9567）：`n≥3 → +3`，`n==2 → +2`，`n==1 → +1`（注释"坎 1~3 胡"）。

**赖子**（9569-9573）：若无"某红精恰好 2 张"（否则赖已被计入双精的 +14），则每个赖子 `+6`（通配枢纽价值）。

**红固定顺**（9575-9579）：`[上,大,人]`、`[可,知,礼]` 三字齐 → 各 `+1`。`七十土` 只注释不计数（"三字齐=1胡+精七逐张，已计入精牌潜力，不重复"）。

### 4.2 如何用进出牌

- `_curPot = _aiHuPotential(hand, preMelds)` 作为当前基准（9692）。
- 对每个候选，算出打出后的 `potDelta = curPot.potential − potential(打出后)`（9716-9719），潜力损失在非听牌分支里 `− potDelta×8`（9797），大胡方向再加 `− potDelta×6`（9802）。
- 效果：精牌/赖子被打出会立刻造成大 `potDelta` → 被强烈惩罚 → AI 自动保留精牌。

## 5. 记牌与危险规避

### 5.1 记牌（`getRemainingCount`，2453）

```
getRemainingCount(ch) = max(0, G_CARD_TOTALS[ch] − G_discardCount[ch] − 庄家手牌中 ch 的张数)
```

- `G_CARD_TOTALS`（2438-2443）：普通字 5 张，`赖` 2 张。
- `G_discardCount[ch]`（2445-2452）：`trackCardUsed` 在**每次摸牌**时 `+1`（庄家摸牌/旁家摸牌/招·扎·穿·泛后摸牌等，见 grep 结果 3436/3513/3597/3764/3990/4576/4852/5002/5031/5117/5182/5232/5805/7470/7723/7745）。**出牌不减**（注释"出牌不消耗余牌"）。`trackDeal` 已被移除（2744 注释："trackDeal已移除 — 改为在每次摸牌时记录"），所以发牌不计入。
- 庄家手牌张数直接读 DOM `#hand-zone` 的 `.card-char`（2457-2468），带花牌反向映射。

> **诚实标注**：这是**近似口径**，不是严格的"牌墙剩余"。它 = `总张数 − 已摸走的张数 − 庄家当前手牌`，**未扣掉两位旁家手牌、也未扣明牌区/弃牌池**。因此它的绝对值不是"还能摸到几张"，实际只被当作一个**稀缺度分级信号**（阈值 0/1/2）来用。同时，`getRemainingCount`、`exposureScore` 都直接读 DOM，本质是**老千视角的"上帝信息"**，不是合法推理。

### 5.2 危险牌（`getDangerScore`，2568）

返回 0~1 危险度，对两位旁家取 `max`，由三块来源合成：

- **P0 过牌折扣**（2573-2576）：该旁家曾"过"这张牌（`G._passRecord`）→ `passDiscount = 0.3`（危险降到 30%）。
- **听牌置信度**（`guessOpponentTing`，2500）：`danger = conf × scarcity × handPressure × passDiscount`，其中
  - `scarcity`：外部剩余 `≤1 → 2.0`，`≤2 → 1.5`，否则 `1.0`（2581）；
  - `handPressure`：旁家手牌 `≤5 → 1.5`，`≤8 → 1.2`，否则 `1.0`（2582）。
- **P1 明牌反推**（2586-2607）：旁家碰/招的字，其顺子伙伴危险度提升 `baseDanger=0.35 × passDiscount`，再乘手牌压力 `≤5→1.8 / ≤10→1.3 / else 1.0`。穿/泛（已 5 张）不再需要顺子，不提危险。
- **P2 行为分析**（2609-2630）：
  - 旁家碰满额（`penCount≥2`）且手牌 `≤8`，且最近没打过该字 → `max(max, 0.5×passDiscount)`；
  - 旁家手牌 `≤3` 且该字外部剩余 `≤2` → `max(max, 0.85×passDiscount)`，否则 `0.6×passDiscount`。

最后 `Math.min(1, maxDanger)`。

### 5.3 期望损失（`getRiskCost`，2637）

与 `getDangerScore` 的"取 max"不同，这是**按各家预期胡数加权求和**，归一化到 0~1：

```
raw   = Σ_旁家 ( conf × scarcity × handPressure × passDiscount × estPoints )
denom = 3.0 × (e1.estPoints + e2.estPoints)
return min(1, raw / denom)
```

`conf` 取 `guessOpponentTing` 与 `_aiBehaviorBasedTingGuess` 的较大值（2649-2658）。`estPoints` 来自 `_aiEstimateOpponentHu`（见第 6 节）。分母 `3.0` 是 `conf=1 × scarcity=2 × pressure=1.5` 的上界，保证分家差异不被归一化抵消。

在 L3 出牌里，危险惩罚 = `danger×20 + riskCost×30`（9756），响应放铳成本也用 `riskCost×30` 同量纲（`RESP_RISK_WEIGHT = 30`，8747）。

## 6. 对手建模

### 6.1 读桌面估对手（`_aiEstimateOpponentHu`，8844）

带缓存（`_aiHuEstCache`，8842，随手牌签名失效）。两段式：

**明牌区（精确查表）**：`meldHu = calcMeldHuTotal(pi)`（5608），只统计 pen/zhao/chuan/fan 的胡数，逐副走 `calcMeldHu → _calcMeld` 查表（含主精判定）。

**暗牌（启发式）**：对手牌各字面张数估算 `darkHuMin / darkHuMax`（8854-8879）：

| 字面 | darkHuMin | darkHuMax |
|---|---|---|
| 赖 | cnt×2 | cnt×4 |
| 红精（三五七） | cnt≥3→5，否则 1 | cnt≥3→10，否则 2 |
| 黑精（乙九） | cnt≥3→1，否则 0 | cnt≥3→3，否则 1 |
| 非精字 | cnt≥3 且红→2 / 黑→1 | 同左 |

`estHu = meldHu + round((min+max)/2)`（8881）。

**换算成分数**（8883，精确规则）：

```
estPoints = estHu >= 17 ? calcPoints(estHu) : (estHu / 17 × 3)
```

其中 `calcPoints(hu) = 3 + _huTier(hu)`，`_huTier(hu) = floor((hu−17)/5)`（6557-6565），即 **17–21 胡 → 3 分，22–26 → 4 分，…**（每 5 胡一档）。`estPoints` 是止损/危险/喂牌所有"胡数差距"判断的统一量纲。

### 6.2 旁家听牌猜测

- `guessOpponentTing`（2500）：明牌区顺子伙伴（`c=0.45`）→ 最近出牌的反推（`c=0.2`）→ 少牌时已知手中牌推缺牌（`c=0.35`）→ 高频弃牌降权（`×0.5`）。合并去重取最大置信度。
- `_aiBehaviorBasedTingGuess`（8945）：碰满额且手牌少时推顺子伙伴（`0.5`）；手牌 ≤3 时推缺牌（`0.65`）。详见 `_aiAnalyzeOppBehavior`（8917）。

### 6.3 跨局玩家建档（Phase 10，**含一个重要坑**）

设计意图（9585 注释）：**老千专属，localStorage，只统计人类（位 0）的桌面可见行为**。

- `_profLoad`（9586）读 `localStorage['hp_profile_v1']`，结构 `{games, pen:{}, zha:{}, disc:{}}`。
- `_profSave`（9589）、`_profRecord`（9590，**只记 `pi===0`**）、`_profGameDone`（9598，`games++`）。
- 在 L3 里用（9708-9709）：`_profOk9 = games >= 3` 才启用（"档案不足 3 局不启用，样本纪律"）。启用后（9765-9769）：人类爱碰/扎的字 `dangerPenalty += min(10, 次数×2)`，人类常打的字 `dangerPenalty ×= 0.9`。

> **诚实标注（疑似死代码/作用域缺陷）**：这 4 个 `_prof*` 函数的定义**物理位置在 `_aiL3Cheat` 函数体内部**（9586-9601，被 9584 的 `{` 与 9960 的 `}` 包住）。按 JS 函数作用域规则，它们是 `_aiL3Cheat` 的**局部函数**，不是全局函数。因此：
> - 记录调用点 `_profRecord(0, 'discard', char)`（3152）、`_profRecord(0,'pen',ch)`（3695）、`_profRecord(0,'zha',ch)`（4504）、`_profGameDone()`（5398 / 7224）都在 `_aiL3Cheat` **外部**，运行时会是 `ReferenceError`。
> - 其中 3695 / 4504 / 5398 / 7224 有 `try/catch` 包裹（静默吞掉），但 **3152 是裸调用**（无 try/catch），人类出牌时会抛未捕获异常（会跳过紧随其后的 `setPhase('等待响应')`，见 3154）。
> - 只有 `_aiL3Cheat` **内部**的 `_profLoad()`（9708）能正常执行；但因为 `_profGameDone` 在外部不可达，`games` 永远不增 → `_profOk9 = games>=3` 恒为 false → **Phase 10 的"跨局习惯"调整实际上从不生效**。
>
> 结论：这段跨局建档在当前构建里是**惰性/失效代码**。若这是笔误（本意应放在全局作用域），需要把 9586-9601 这段移到 `_aiL3Cheat` 外面才能工作。

## 7. 攻防动作决策

### 7.1 碰（限两次 / 第三次捉铳）

- **规则层限两碰**：`oppPenCount >= (G._penLimit || 2)` 时跳过碰（3200 / 3306 / 3337 / 4970 等多处）。"第三次碰必须直接胡牌"由"吃统=捉铳"路径兜底：第 3 碰的机会只能通过 `_aiCheckOpponentChi`（9176）的"吃进即胡"成立，不存在"碰后听牌"。
- **AI 决策**（`_aiDecidePen`，8450）：菜鸟恒碰；L1+ 走 `_aiPenBenefit`（8276）：
  - 碰后/碰前听牌改善（8304-8309）、红碰 `+1×5`（8299/8311）、口连接损失 `−8/个`（8329）、记牌 `remain≤1→−10 / ≥3→+3`（8332-8334）、放铳否决（8337-8345：`forcedRisk.minRisk > RESP_SAFE_LINE(0.25)` 且无安全牌 → 拒绝）。
  - **阈值**：`baseThreshold = L1→−9 / L2→−5 / L3→−2`（8464），L2+ 再加阶段 `penThreshold` 与防守 `+2`（8465-8471）。`benefit >= threshold` 才碰。
  - 调参开关：`G._penForce`（恒碰）、`G._penNoReject`（跳过放铳否决）。

### 7.2 招牌（招）

- **旁家 AI 不做招**（`checkResponseAfterOpponent` 对旁家只处理泛/碰，不处理招）。招是庄家动作。
- `_aiDecideZhao`（9348）定义了"招牌收益"逻辑（招后听牌 `+40+maxHu×5`、红精 `+10`、泛牌前提 `+6`、口损失 `−5/个`、阈值 L1→−5/L2→0/L3→5），但它用 `_buildPreMelds(0)`（庄家侧），且**全文件无调用点**（grep 无 `_aiDecideZhao(` 调用）→ **当前是死代码/预留**。

### 7.3 泛（泛牌）

- **无条件自动**：`checkResponseAfterOpponent`（3330-3334）里，旁家手上该字 `≥2` 且已有同字 `zha` 明牌 → 直接 `opponentFan`，无 AI 收益判断。

### 7.4 穿（穿牌）

- **无条件自动**：`opponentAutoPlay`（5113-5185）里，扎后摸牌底摸到同字第 5 张 → 直接升穿（无决策分支）。

### 7.5 扎（暗杠）与"忍扎三问"

- **触发**（5034-5057）：4 张同字（非赖）优先；否则赖子精扎（三五七中 `n≥2` 且 `4−n ≤ 赖数`，取物理张数最多者）。
- **AI 决策**（`_aiDecideZha`，8478）：L0/L1 恒扎；L2+ 走 `_aiZhaBenefit`（8351，扎后听牌 `+30+maxHu×3`、穿牌潜力 `+8/+5`、红精 `+5`）。
- **L3 附加**（8486-8542）：发展阶段直接扎、冲刺期听评估；扎前后听牌对比（"已听牌但扎后不听且收益<10 → 不扎"；"没听牌但扎后能听 → 扎"）；**忍扎三问**（8530-8541，注释指向 10号/11号文档）：
  - `_weak9 = 起手潜力 < 12`（弱牌）：只有"余牌 ≤30% 且收益 ≥8"才扎，否则忍（绝境才扎）。
  - 非弱牌：需"扎后能听 / 结构听 / 收益 ≥12"（`_q1`）或收益 ≥15，否则忍。

### 7.6 扎/穿席位重指派（判胡引擎，**精确规则**）

`_huFlexPick`（6780）是自摸/捉铳判胡用的**精确规则**，不是启发式。核心：手上的扎牌对旁家不可见，所以**扎的席位与"赖的分配"都可重选**——把手上所有扎牌放回同一个池，逐一枚举每个扎席位"不成立 / 扎 4 张（N 本字 + 4−N 赖，N=4/3/2）/ 穿 5 张（N=5/4/3）"，取最高胡数。附两条铁律：

- 赖子只能通配精牌三五七（`WILD_USABLE`，6796-6797），不能配"人"等非精字。
- 胡牌结构必须 **8 圆句 + 1 眼**（6815-6824），7+2 不算胡。

### 7.7 自摸 / 捉铳

- **自摸**（`checkOpponentHu`，6948）：`aiLevel===0` 直接返回 null（菜鸟不检测自摸）；L1+ 走 `_huFlexPick` 完整判定。调用点在 `opponentAutoPlay`（5240）与"不扎分支"（5064）。
- **捉铳**（`checkOpponentHuWithCard`，6959）：`aiLevel===0` 且 `Math.random()>0.05` 返回 null（菜鸟 5% 概率捉铳）；L1+ 完整判定，统牌打 `isTongCard` 标记。调用点在 `checkResponseAfterOpponent`（3277）与旧响应路径（7800）。

## 8. 喂牌 / 放铳风险 / 止损

### 8.1 止损模式（`_aiGetConcedeMode`，8799）

三条件**同时满足**才进入止损（8834）：

1. **自己弱牌**：`jingScore ≤ 1.5`（赖×3、红精×1.5、黑精×1 加权）**且** `kanCount ≤ 1` **且** `kouCount ≤ 2`（8804-8817）。
2. **旁家威胁**：两家 `estPoints` 最大值 `≥ 3.5`（8820-8826，与 `_aiGetResponseThreat` 同阈值 8756）。
3. **晚局**：`G.deckCount / 总张数 ≤ 0.45`（8829-8832）。

止损行为：放弃胡牌，只打绝对安全牌（`dangerThreshold` 降到 0.25），保留价值 `×0.4`（允许拆对子/坎，9740），听牌权重从 10000 降到 1000（9790-9791）。

### 8.2 喂牌目标（`_aiGetFeedTarget`，8698）

止损模式 + 两家分差明显时，挑"便宜家"主动喂（让便宜家先胡，压低放铳给危险家的损失）：

- 便宜家 = `estPoints` 较小者，危险家 = 较大者（8706-8707）。
- 需 `diff ≥ 1.0` **且** `便宜家 estPoints > 0.5` 才启用（8710）。

### 8.3 喂牌评分（`_aiFeedScore`，8715）

- 便宜家需要 `ch`（`guessOpponentTing` 置信度 ×2 + `_aiBehaviorBasedTingGuess` 置信度 ×2）→ 加分；
- 危险家需要 `ch`（×3 计负）→ 重罚（8728-8735）；
- 便宜家曾过此牌 → `−1`（8736-8739）。

在 L3 出牌里：`feedScore>0.5` 时危险惩罚 `×0.25`（9759），非听牌分支 `+ feedScore×30`（9817），兜底时优先喂高分（9940-9951）。

### 8.4 放铳风险常量

- `RESP_SAFE_LINE = 0.25`：响应后最安全可打牌的风险阈值（>即"无安全牌可打"，8746）。
- `RESP_RISK_WEIGHT = 30`：放铳成本扣益系数（与 L3 `riskCost×30` 同量纲，8747）。
- `_aiForcedDiscardRisk`（8761）：模拟"响应后被迫出的最安全牌"对非响应旁家的期望损失（过牌 `×0.3`、稀缺 `×2.0/1.5/1.0`、手牌压力 `×1.5/1.2/1.0`）。

## 9. 人味

### 9.1 ε 随机扰动

- 默认表 `{0:0.10, 1:0.15, 2:0.075, 3:0.015}`（8225-8226），**L3 = 1.5%** 概率随机出一张，避免"每手都是最优解"的机械感。

### 9.2 连败保护（sticky ε，8149-8157）

- `hu_streak` 存 localStorage：旁家赢 → `+1`，玩家赢 → 清零，流局 → 保持。
- `_stickyEase()`：连败 `<2` 返回 0，否则 `min(3, streak−1)`（0~3 档）。
- 在 `_aiPickDiscardCore` 里：`ε += ease × 0.05`（最多 +15%），**只作用于旁家 AI**（`playerIdx !== 0`）。即玩家连败时旁家"出牌随机度递增"，营造呼吸感，而非直接放水改判胡。

### 9.3 思考延时（`_aiThinkDelay`，8163）

- 分级基准 `[380, 520, 680, 860][lv]`，**L3 = 860ms**，再 `+ Math.random()×120` 抖动 → 860~980ms。
- 注释（8160-8161）：用"想多久"表达强弱，菜鸟随手打、老千深思。

## 10. 性能预算

- `_aiPerfStart(budget)`（9144）：`maxTime = budget || 120`，`maxCalls = 800`，计时清零。`_aiL3Cheat` 与 `_aiSmartDiscard` 都调 `_aiPerfStart(120)`（9603 / 9432）。
- `_aiPerfCheck()`（9151）：每次调用 `callCount++`，超 `maxCalls`（800 次）或超 `maxTime`（120ms）返回 `false`。L3 候选循环里 `if (!_aiPerfCheck()) break` 做**超时中断**（9633、9503）。

1. **荒庄是主要瓶颈**（胡牌率 35.3% vs 目标 65–85%）。可选讨论方向：
