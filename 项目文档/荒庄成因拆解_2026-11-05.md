# 荒庄成因拆解（2026-11-05）

> 对象：`main` @ `1ec3baa`（基线提交之后）
> 目的：回答"荒庄卡在哪一步"——听不了 / 听牌被截 / 摸空。
> **本轮没有改动任何游戏逻辑**，只加了测量探针。

## 0. 一句话结论

L3（老千）的荒庄里，**73% 是"牌型根本没成形"**，不是胡数不够、也不是听牌被截；而"成形"的最大障碍是**庄家每局只有约 7~9 次换牌机会**（牌墙 36 张）。
另外在量化过程中发现两个比 AI 参数更重要的结构问题（第 4 节）：**测量器缺了扎→穿的升级流程**、**庄家没有成形用的"吃"通道**。

## 1. 方法（可复现）

- `measure_winrate.js` 新增只读钩子 `opts.onRest(vmctx, tag, ctx)`，在三种静息态回调：
  `deal`（起手）、`turn`（庄家回合开始前）、`claim`（庄家碰/招后出牌）、`final`（终局）。
  不传 `opts` 时行为与旧版完全一致（已交叉校验）。
- 新脚本 `analyze_draw_cause.js`：在每个静息态对庄家手牌+明牌做
  ① 逐字补一张 → `analyzeHand`（≥17 胡，真能胡）
  ② 同一次 → `analyzeHandLoose`（能拆出牌型，不看门槛）
  并记录牌墙剩余、听口数、听口在牌墙/对手手中的张数。
- 交叉校验：同 300 局，`measure_winrate` 位0 34.7%，拆解器 34.7%（104 局）——一致。

### 口径与已知边界（重要）

1. **不含"升级胡"**：本探针只模拟"补一张进手牌"，**不含**"摸到第 5 张把扎→穿、招/招牌→泛"的升级路径（见第 4.2 节）。
2. **不含庄家吃牌通道**：庄家（位0）在页面里没有吃牌操作，只有 胡/招/碰/扎（见第 4.1 节）。
3. 听牌定义与页面 `detectTing()` 同口径（页面自己的听牌提示也只做"补一张"检测），所以口径本身与游戏一致。

## 2. 结果一：荒庄归因（互斥三类）

seed `20261027`，庄家=位0，陪练=2×高手。

| 类别 | 含义 | L3 老千 300 局 | L1 高手 200 局 |
|---|---|---|---|
| A1 | 全程未成形（牌型从头到尾拆不出来） | **109 局 / 73.2%** | **134 局 / 88.2%** |
| A2 | 成形过但从未进胡（胡数始终不够 17） | **0 局 / 0.0%** | **0 局 / 0.0%** |
| B | 进过胡（真听过）但牌墙耗尽未胡 | **40 局 / 26.8%** | **18 局 / 11.8%** |
| — | 荒庄合计 | 149 / 300（49.7%） | 152 / 200（76.0%） |
| — | 庄家胡 / 旁家胡 | 104（34.7%）/ 47（15.7%） | 18（9.0%）/ 30（15.0%） |

- 庄家平均出牌回合数：L3 荒庄 9.2／胡牌 6.8；L1 荒庄 8.9／胡牌 6.1
- **天胡（起手 26 张即胡）：两档都是 0 局**
- A1 局里"成形时最高胡数"平均：L3 3.4 胡、L1 1.0 胡——不是差一点，是根本没搭起来
- 级别越高 A1 越低（73% vs 88%）、B 越高（27% vs 12%）：老千确实在"把牌往成形方向拉"，方向没错，只是量不够

## 3. 结果二：首次进胡时机（B 类荒庄 vs 胡牌局）

| 首次能胡时牌墙剩余 | B 类荒庄 | 庄家胡牌局 |
|---|---|---|
| 0~3（≤1 次摸牌） | 13（32.5%） | 1（1.3%） |
| 4~6（≤2 次） | 7（17.5%） | 9（11.4%） |
| 7~12（≤4 次） | 11（27.5%） | 26（32.9%） |
| 13~18（≤6 次） | 5（12.5%） | 9（11.4%） |
| 19+（7 次以上） | 4（10.0%） | 34（43.0%） |

- **B 类荒庄首次能胡时，牌墙只剩 8.4 张（≈2.8 次摸牌）；胡牌局是 16.3 张（≈5.4 次）。差约 2.5 轮。**
- B 类首次能胡的听口平均 2.3 个，但听口在**牌墙里只剩 0.5 张**、被对手捏着 4.5 张——即便听上也基本摸不到。
- 荒庄局里终局仍在听的只有 23.5%，终局能成形的 34.9%。
- L1（高手）同样形态但更极端：B 类首次能胡时牌墙 11.0 张 vs 胡牌局 17.8 张，B 类只占荒庄 11.8%——高手连"进听"都很少做到。

## 4. 结构性发现（比调 AI 更关键）

### 4.1 庄家没有"吃"通道

- 页面 `checkResponseAfterOpponent()`（L3215）给庄家的选项只有 **胡 / 招 / 碰（+扎/穿自摸流程）**，没有吃。
- 旁家走 `_aiCheckOpponentChi()` → `opponentChi()`（听牌专用），**可以吃**。
- 规则文档 §3.4/§7.2 写的是"统牌只能形成碰牌或吃牌（顺子）"、"庄家用该牌碰牌或吃牌形成顺子后满足胡牌条件"——**庄家在捉铳时确实能组顺子胡**（`simCards` 把统牌当手牌喂给 `analyzeHand`），但**没有用于搭牌型的吃**。
- 后果：庄家每局实际的结构加速手段只有 碰/招/扎（且碰限两碰），比旁家少一条。人类坐庄体感吃亏，与此一致。

### 4.2 测量器缺"扎→穿 / 招→泛"升级流程（影响基线可信度）

- 页面 `dealerCheckChuan(ch, isWildZha)`（L4468）负责：扎牌后摸底 → **摸到同字即升级穿牌 → 立刻做自摸胡检测**。
- 测量器的 `runDealerTurn` 只做了"摸底这张牌"，**没有检测同字、没有升级、没有随之而来的自摸胡**。
- 量级不低：本 300 局终局明牌合计 766 组，其中 **招（4 张）222 组 + 扎（4 张）46 组 = 35%**，每组都只差 1 张就能升穿/泛，而穿牌价值 56~96 胡——一旦升上去，基本等于直接胡。
- 结论：**当前 58% 荒庄 / 28.5% 老千胡率是"下限"，真实页面里应更高。** 在修好这把尺子之前，按现有数字调 AI 有系统性偏差风险。

### 4.3 硬约束：牌墙只有 36 张

112 张牌，起手 26/25/25 摊掉 76 张，墙剩 36 张。三家轮流摸 + 碰/吃摸底消耗，**庄家整局实际只拿到 7~9 次换牌机会**，每次只能换 1 张。老千要先"成形"再"进听"再"摸到"，9 次换牌里要完成三次跃迁——这是荒庄率的天花板来源，也是任何 AI 调参都绕不开的物理约束。

## 5. 建议的动手顺序（待拍板）

| 顺序 | 动作 | 为什么先做 | 是否改游戏逻辑 |
|---|---|---|---|
| 1 | 给测量器补 `dealerCheckChuan`（扎→穿升级 + 升级后自摸胡） | 不先修尺子，后面所有数字都偏悲观 | 否，只改 harness |
| 2 | 重跑基线（L0~L3 + 体验桌） | 得到真实荒庄率，判断还差多少 | 否 |
| 3 | 若荒庄仍 >45%：给庄家补"吃统"通道（规则文档支持，旁家已有） | 庄家成形通道少一条，是人类体感吃亏的根因之一 | 是，需你确认规则本意 |
| 4 | 最后才是 AI 旋钮（ε / 碰门槛 / 进取吃） | 前三步没做，调旋钮等于对着失真数据拧螺丝 | 是 |
